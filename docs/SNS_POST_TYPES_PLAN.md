# SNS投稿の「型」機能 実装計画 v2（2026-10-18 実装済み）

> この計画は実装済みです。実際の仕組みは docs/REELS.md を参照。計画と違う点：型の作り直し回数は `services.MAX_HOOK_REGENERATIONS`、おすすめの重みは `settings.SNS_RECOMMEND_WEIGHTS`、動画の自動作成は個人情報・誇大表現のチェックを通ったときだけ。

v1 への回答「推奨で進める。ただし、同じ機能が2つにならないように。素材（写真・動画）を入れやすく、カットやシャンプーの動画を入れたら出来上がる形に。使いやすさと効果が最優先」を受けて作り直しました。

## v1 からの変更点

| v1 | v2 |
|---|---|
| 「文章の投稿」（drafts）を拡張し、「動画」（reels）とは対応表でつなぐ | **SNS投稿の仕組みを1つに統合**。`apps/reels` を唯一の仕組みにし、「文章の投稿」の画面は閉じる（過去の投稿は履歴で読める） |
| 型は 文章5つ ＋ 動画7つ | **型は5つだけ**。動画の撮り方（7つの構成）は型の中に隠す |
| 型を選んでから素材 | **素材から始める**。入れたものに合わせて出来上がる形（動画／フィード／ストーリーズ）が決まる |
| 新アプリ `snsplan` と設定画面を追加 | 新アプリ・新設定画面は作らない。既存の SNS設定に「投稿の軸」を足す |

## 1. 型（5つ）と、出来上がる形

| 型 | 狙い | 出来上がる形 | 必要な素材 | 動画のときの構成（既存の7つを再利用） |
|---|---|---|---|---|
| ビフォーアフター | 指名・予約 | **動画**（写真だけでも動画になる）＋キャプション | アフター写真1枚 ＋ ビフォー（写真か動画）1つ | before_after |
| 工程リール | 信頼・初めての人 | **動画** | 施術中の動画1本以上（カット・シャンプー・塗布・ブロー） | process |
| 似合わせ提案（作品集） | 保存・指名 | フィード複数枚（動画があれば動画） | アフター写真2枚以上 | color_catalog |
| お役立ち | 保存・再来 | フィード複数枚（手元の動画があれば動画） | なし（写真1枚あると良い） | care_tips |
| 人柄・考え方 | ファン化・初めての人 | ストーリーズ（本人の動画があれば動画） | なし | self_intro（初回）／ stylist_story ／ daily（朝〜夕の素材があるとき） |

**出来上がる形のルール（迷わせない）**
- 動画を1本でも入れた → 動画（mp4）を作る。キャプション・ハッシュタグも一緒に出す。
- 写真だけ → 型の主な形式。ビフォーアフターだけは写真だけでも動画にする（動く方が効果が高いので）。
- 素材なし → お役立ち・人柄だけ選べる（文字で作る）。
- 動画の中身は既存のエンジン（台本 → FFmpeg → BGM → AIの声）。**カットやシャンプーの動画を入れると、いちばん動きのある3秒を自動で選び、テロップと声を付けて仕上がる**（3秒の自動選択は既存機能）。

## 2. 導線（画面はこれだけ）

### 入口
- SNSタブ: ボタンは「投稿をつくる」の1つ。上に「今週のおすすめ（○本）」カード。
- カルテ詳細: 「この施術で投稿をつくる」の1ボタン（今の「投稿文を作る」「動画を作る」の2つを1つに）。
- 今日の画面: 「今週のおすすめ」カード。

### 4ステップ（1画面ずつ、戻れる）
1. **素材を入れる**
   - 写真と動画をまとめて選ぶ（スマホのアルバムから複数選択／その場で撮る／カルテから取り込み）。カルテからは掲載OKの写真だけ自動で入る。
   - 役割（ビフォー／アフター／施術中／本人）は自動で推定し、サムネイルをタップで直す。推定は「撮影日時が早い＝ビフォー、遅い＝アフター、動画＝施術中」。AIキーがあれば写真を見て推定し直す。
   - 顔が写っている印も同じ画面でタップ。
   - 素材なしでも次へ進める。
2. **型を決める**
   - 上に「AIのおすすめ：ビフォーアフター」と理由1〜2文、次点2つ。「おすすめで作る」／「自分で選ぶ」。
   - 自分で選ぶ: 5つのカード。素材が足りない型は薄く表示し「ビフォー写真を1枚足すと選べます」。押すと撮影ガイド（既存のカメラ枠）が開いてその場で足せる。
3. **フックを選ぶ**: 3案（呼びかけ／結果先出し／悩みの映像／意外性／地域から、型に合う3種類）。「作り直す」は3回まで。
4. **出来上がり**
   - 動画のとき: プレビュー → 「Instagramに投稿」（連携済みなら予約投稿、未連携なら保存してコピー）。
   - フィードのとき: 1枚目〜最後の枚の文字。ストーリーズのとき: 短文＋スタンプ案。
   - 共通: キャプション（誰向け／何が解決／所要時間／料金の目安／持ち／予約方法）・ハッシュタグ・表紙の文字・テロップ一覧。項目ごとにコピー。
   - チェック表示: 個人情報（残っていれば投稿済みにできない）・誇大表現・6要素の抜け。
   - ボタン: 投稿済みにする／スキップ／台本を直す（既存の編集画面）。

### 履歴と設定
- 履歴（既存の「記録と数字」に統合）: 型の内訳（直近10件の帯グラフ。同じ型の連続が見える）、投稿ごとの成果の手入力（保存・プロフィールアクセス・予約リンククリック・DM・インスタ経由新規）、型ごとの平均。ストーリーズ用の計測リンク（既存の /r/コード/）を投稿ごとに発行し、クリックだけ自動で数える。
- 設定（既存のSNS設定に追加）: 得意な悩み1〜3個（インタビューQ4の回答とカルテの悩みから候補を出す。自由入力可）、投稿の目的、よく使う型・避けたい型、週の投稿本数（今の「月○本」を置き換え）。

## 4. おすすめロジック（ルールで計算。理由文だけAI）

1. **候補を絞る**: 必要な素材が無い型は外し、「何を足せば選べるか」を一緒に返す。避けたい型も外す（手動では選べる）。
2. **スコア**（重みは `settings.SNS_RECOMMEND_WEIGHTS`、環境変数で上書き）
```
score = 目的3.0 × 相性(型,目的)
      − 偏り4.0 × 直近5件に占める割合
      − 連続3.0 × [直前と同じ型]
      + 空き枠2.0 × 空きの多さ × 予約導線の強さ(型)      … 空き枠データが無ければ0
      + 成果2.0 × 縮小係数 × 成果の偏差(型)              … 件数÷(件数+3) で縮小
      + 好み1.0 × [よく使う型]
      + 採用1.0 × 縮小 × (採用率−0.5) − スキップ1.5 × 縮小 × スキップ率
```
   - 空きの多さ = min(1, 今後14日の空き時間 ÷ 週の稼働時間)。未設定なら10時間とみなす。
   - 成果 = 予約リンククリック×3 ＋ DM×3 ＋ インスタ経由新規×5 ＋ プロフィールアクセス×1 ＋ 保存×0.5。
   - 相性（初期値）: ビフォーアフター 指名1.0／平日昼0.9／初めて0.5／再来0.4、工程リール 0.7／0.5／0.9／0.3、似合わせ 0.8／0.7／0.6／0.6、お役立ち 0.4／0.3／0.6／1.0、人柄 0.6／0.3／1.0／0.4。予約導線: 1.0／0.6／0.7／0.3／0.3。
3. **出力**: おすすめ1つ＋理由（加点・減点の大きい材料2つから。AIキーが無ければ定型文）＋次点2つ。
4. **テーマ**: 素材のカルテの悩みが得意な悩みに近ければそれ。無ければ、最近いちばん使っていない得意な悩み。
5. **今週のおすすめ**: 週の本数 − 今週作った本数 だけ提案。1本目を直近に加えて2本目を計算（同じ型・テーマが並ばない）。

## 5. 生成（2段階）

- **AIに渡すもの**: 型・テーマ・目的・一般化した悩みと結果（ストーリー掲載OKのときだけ。既存の一般化処理）・施術の要約と仕上がり（`sns_safe_fields`）・素材の役割と枚数・人柄エピソード1つ（既存の選び方）・文体設定・サロンの場所と地域タグ・料金と所要時間と持ち（料金表から該当メニュー）・予約リンクの有無。
- **渡さないもの**: 顧客名・呼び名・非公開メモ・要望・来店日時・カルテ本体・写真のメモ。
- **フック**（1段階目）: 3案＋最初の2秒の映像の指示。誇大表現に引っかかった案はAIに1回直させる。
- **本文**（2段階目）: 選んだフックを冒頭に固定。動画なら既存の台本生成（型・フック・テーマを足す）→ 動画化。フィード・ストーリーズは新しい出力（JSONスキーマ）。
- **チェック**: 個人情報（既存＋職業・私生活の語）／誇大表現（絶対・誰でも・必ず・100%・劇的・激変・魔法・一瞬で・最強・日本一・No.1）／キャプションの6要素。
- 型ごとのプロンプトは `apps/reels/prompts/types/` に1型1ファイル。

---

## 6. テスト（AIはすべてモック）
おすすめ（偏り・連続・素材なし除外と「足すもの」・目的・空き枠の有無・好み・成果が少ないときの縮小・採用／スキップ履歴・今週のおすすめの重複なし）／生成（渡す文字列に顧客名・非公開メモ・来店日が無い。掲載NGの写真が入らない）／誇大表現・6要素・個人情報で投稿済みにできない／画面の一連の流れ（素材 → 型 → フック → 出来上がり → 投稿済み／スキップ）／提案への反応の記録／テナント分離／旧画面の転送。

## 7. 実装の順番
1. 型マスタ（5つ＋構成の対応）・SNS設定に「投稿の軸」・デモの初期値
2. モデル追加とマイグレーション（素材の役割・カルテ写真の役割・料金表の持ち・投稿の項目・提案）
3. おすすめロジック・重み・今週のおすすめ・テスト
4. 素材画面（まとめて選ぶ・役割の推定とタップ修正・カルテから取り込み）
5. フック生成・誇大表現チェック
6. 型ごとの本文生成（動画は既存エンジンへ、フィード・ストーリーズは新規）・6要素チェック
7. 出来上がり画面（タブ・コピー・投稿済み／スキップ）・履歴と成果入力・計測リンク
8. 入口の整理（SNSタブ・カルテ詳細・今日の画面）、旧「文章の投稿」の転送、ドキュメント、デモデータ、通しのテスト
