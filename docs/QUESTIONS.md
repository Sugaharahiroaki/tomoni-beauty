## B. 本番環境について教えてほしいこと

1. さくらVPSの OS（Ubuntu 24.04 を想定）、ドメイン名、TLS（certbot を想定）
2. GitHub リポジトリの所有者（Organization か個人か）。デプロイ用 Secrets（`SSH_HOST` `SSH_USER` `SSH_PRIVATE_KEY`）を誰が設定するか
3. n8n は同じVPSに置くか、別ホスティング（n8n cloud）か
4. メディア（施術写真）の保存先: VPS ローカル（現状）か、オブジェクトストレージ（さくらのオブジェクトストレージ / S3互換）か。写真は現状 URL を知っていれば閲覧できるため、本番前に認証付き配信か署名付きURLにすることを推奨
5. 試験運用 5 名の LINE 公式アカウントは各自が開設済みか（Messaging API 有効化の手順書は設定画面内に記載）

## D. 実装中に行った小さな判断（報告のみ）

- お客様の「呼び方」（`call_name`）を追加。未設定なら「姓＋さん」で文面に差し込む。
- メモ内の「写真OK・顔出しNG」等の言及は **自動反映せず**、カルテ画面に「設定に反映」ボタンを出す（同意は美容師の確認を経て記録）。
- LINE友だち追加で自動作成された顧客は `要確認` バッジ付きで表示し、既存顧客への統合機能を用意。
- 文面の `{予約リンク}` は、ホットペッパーURL未設定の美容師では行ごと削除される。
- SNS投稿の個人情報チェックで error が残る場合、「投稿済み」にできない（修正→再チェックが必要）。「○○さん」は warning（確認のみ）。
- Push 送信後はローカルで通数を +1 し、日次バッチで LINE API の実測値に上書き同期。
- 内部エンドポイント（n8n用）はトークン必須。`INTERNAL_API_TOKEN` 未設定なら常に 403。
